## Findings for this machine and the OBSBOT Tiny 2

Observed locally: **Linux Mint 22.3 (Zena), Cinnamon, X11, Python 3.12.3**.
No `/dev/video*` device was exposed during validation. SDL2, TurboJPEG,
PyGObject, ALSA and spnav libraries are present. Camera capture, physical gimbal
movement, real portal authorization and preset persistence on the Tiny 2 have
not been hardware-tested.

### Use the source GUI first if preview is black

[Issue 113](https://github.com/soyersoyer/cameractrls/issues/113) reports a black
Flatpak preview on Mint 22.3/X11 even with TurboJPEG and camera permission
present; the source build works on that reporter's machine. It is a C920 report,
not proof of a Tiny 2 defect. [Issue 122](https://github.com/soyersoyer/cameractrls/issues/122)
reports the same symptom on Mint 22.2 without a confirmed cause.

From this checkout, run:

```sh
python3 cameractrlsgtk.py
```

That uses the reviewed source and host libraries. For a Flatpak-only failure,
try this temporary diagnostic before changing persistent overrides:

```sh
LIBGL_ALWAYS_SOFTWARE=1 flatpak run hu.irl.cameractrls
```

Software rendering was reported to resolve an older Flatpak preview failure in
[issue 6](https://github.com/soyersoyer/cameractrls/issues/6). It may cost CPU and
has not been established as the cause or fix for issues 113/122 or this machine.
Keep a rendering failure separate from capture-buffer exhaustion, device
contention, and unsupported stream formats.

### Tiny 2 Lite zoom report is unresolved

[Issue 81](https://github.com/soyersoyer/cameractrls/issues/81) describes maximum
zoom on **Tiny 2 Lite**, with inconsistent continuous-zoom values in the GUI and
preset. One Anker user reports a similar symptom. There is no confirmed cause,
patch, control dump or reliable reproduction in the discussion. This does not
establish that the original Tiny 2 has the same bug.

If it occurs on your camera, collect the live control list before/after starting
capture and compare it with the saved preset. Check continuous zoom separately
from absolute zoom. Use the ranges and default reported by that camera rather
than copying numeric values from the Lite or another webcam.

```sh
python3 cameractrls.py --list-devices
# Replace DEVICE with the capture node or its stable /dev/v4l/by-id/... path:
python3 cameractrls.py -d DEVICE --list
```

### Vendor features need a dedicated extension or controller

There is no OBSBOT vendor extension in the reviewed cameractrls code. It can
offer the standard V4L2 controls advertised by the device, but these PRs do not
add Tiny 2 AI tracking, HDR, sleep/wake or vendor presets.

The [Tiny 2 download page](https://www.obsbot.com/download/obsbot-tiny-2) lists
OBSBOT Center for Windows/macOS. OBSBOT separately offers a
[Linux/Ubuntu SDK](https://www.obsbot.com/sdk), with Tiny 2 among the compatible
products. The community [cgevans/tiny2](https://github.com/cgevans/tiny2) project
provides a Linux GUI, CLI, OSC server and V4L2 mapper. These are candidates for
separate evaluation; they were not installed or hardware-validated here.

For a future cameractrls extension, require Tiny 2 VID:PID and extension GUID
matching, documented payload lengths, preservation of unrelated bits, explicit
failure reporting, and real hardware tests. Do not reuse Logitech, Insta360,
Tiny 2 Lite or Tiny 3 command payloads by analogy.

### Select an appropriate capture mode and leave capture to one app

OBSBOT's [Tiny 2 specifications](https://www.obsbot.com/service/products/obsbot-tiny-2)
list MJPEG at 4K30 and 1080p60; YUV has different limits, including 1080p30.
Start with a mode actually enumerated by your device, such as MJPG 1920x1080
at 30 FPS, before testing higher rates. Although the camera advertises H.264,
cameraview lacks H.264 decoding ([issue 34](https://github.com/soyersoyer/cameractrls/issues/34)).

Close cameractrls' preview before starting OBS, a browser call or another
capture application. The current preview uses V4L2 directly and can monopolize
the stream; [issue 71](https://github.com/soyersoyer/cameractrls/issues/71)
proposes PipeWire/portal preview to allow sharing. Parameter control and video
capture are different operations. Other applications can also renegotiate
resolution/FPS ([issue 56](https://github.com/soyersoyer/cameractrls/issues/56)).
